# 对抗性招聘问题目录（problems）

> **这不是对外推广稿，是一份"问题-解法"体系。** 一列列出招聘场景里的真实问题(issue)，
> 每条对应「解决思路 / 对抗性解法 / 对抗性思路」。对内是开发指引，对外是
> "我们为什么这么做"的理念沉淀。

---

## 0. 从第一性原理出发：我们到底在做什么

**一句话定位**：adverhire 不是"招聘测谎仪去刁难候选人"，是**帮助招聘方招到真才实学的人**——
通过系统地"去伪存真"，最大化 **目标(真实能力评估) × 结果(决策依据) 的可靠性**。

四个层层递进：

1. **目标** = 招聘到与岗位匹配的真才实学人才。
2. **手段** = 去伪存真：去除 AI 包装 / 人工包装对真实能力的掩饰。
3. **对抗模型** = 求职 ↔ 招聘双方的信息对抗。求职者会用 AI 包装简历、代写沟通、提词代答；
   我们要从多维度夹击，让伪装失效、让真实暴露。
4. **落地机制** = 每个被识别出的伪装 → 对应"怎么问"→ 提取对决策关键的信息。

一个朴素的判断贯穿始终：**"招聘淘汰/录用的下结论权，绝不交给 AI；AI 只负责把证据抓出来看。**
真正有真才实学的人，不该败给会包装的人；我们保护的正是这一点。

---

## 1. 三条贯穿红线（引擎硬不变量）

1. **坑题永远派生自候选人自述断言** —— 不提出格、无关、无来源的刁难问题。
2. **永不输出"淘汰/录用"结论** —— 只给风险评级 + 证据链，决策权归人工。
3. **目的维护招聘公平** —— 戳穿虚假，保护踏实做事的人。

## 2. 场景 ↔ 关键评估维度映射

求职者会在不同场景用 AI 做不同程度的伪装。下面映射"该场景最该挖的真实能力维度"与
"目录内最典型技法"，面试官按场景查、按技法追。

| 场景 | 该场景最该挖的真实能力维度 | 目录内技法章节 |
|------|--------------------------|----------------|
| **01 · 简历设计与初筛** | 技术栈真实性、量化指标真实性、经历一致性 | AI 注水简历 / 虚报指标 / 技术栈堆砌 / 时间线矛盾 |
| **02 · 在线文字初筛**（邮件/SMS/IM/ATS chat） | 表达真实性、主动性、岗位理解与匹配 | AI 代写回复 / 模板化话术 / 理解空洞(只答不追问) |
| **03 · 远程视频面试** | 实操体感、决策权衡、应变与追问反应 | AI 提词器代答 / 背八股 / 顺杆爬复读 / 追问含糊无具身 |

## 3. 读法（两条路径）

- **开发者 / 维护者路径**：按"对抗思路"里标注的引擎函数名（`trap_tactics` / `detect_signals` /
  `detect_contradictions` / `classify_answer` / `followup_directive`）对到实现，理解为什么这样设，
  迭代时据此增强。方法论的细节见 `.skill/adverhire/references/adversarial-method.md`。
- **面试官路径**：按场景去读对应技法，把"对抗思路"当可执行的 checklist；把"输出决策依据"
  当是否继续推进的参考。
