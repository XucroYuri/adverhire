# adverhire 项目立项文档

> **状态**: 立项 / v0 草案
> **最后更新**: 2026-08-13
> **核心假设**: 先做 Agent 能力，再做壳（界面层）

**传播心智名**：hiredetector（招聘测谎仪）
**正式标识名**：adverhire
**项目类型**：开源 AI Agent 工具 / 企业招聘核验系统
**定位**：国内首个对抗性招聘智能体，专注识别 AI 代答与简历注水，还原候选人真实能力

---

## 一、项目背景与核心痛点

### 1.1 行业背景

生成式 AI 全面渗透求职环节：超 7 成求职者使用 AI 优化简历，超 4 成在远程面试中借助 AI 实时辅助答题。传统面试题库、标准化提问已全面失效，面试官面对"完美回答"越来越难区分真实能力与 AI 生成内容，招聘错配成本持续升高。

当前市场上的 AI 招聘工具几乎全部站在求职者侧（模拟面试、简历润色、刷题助手），招聘方侧的**反作弊、真实性核验**工具处于空白状态，形成显著的攻防不对等。

### 1.2 核心痛点

1. **简历真假难辨**：AI 生成的项目经历光鲜完整，技术栈、量化指标一应俱全，HR 初筛阶段几乎无法甄别注水程度。
2. **面试作弊隐蔽**：远程面试中 AI 实时代答可输出标准化工整答案，常规技术提问难以识别。
3. **核验效率低下**：面试官需花费大量时间设计细节追问、挖掘项目深度，全依赖个人经验，没有标准化方法论。
4. **错配成本高昂**：入职后发现候选人能力与简历严重不符，造成招聘、培训、离职的多重成本浪费。

## 二、产品定位与核心价值

### 2.1 正式定位

**adverhire** = Adversarial Hiring Agent（对抗性招聘智能体）

基于大模型与 Agent 技术，围绕候选人简历生成定制化对抗性面试问题，通过细节核验、体感追问、陷阱验证等策略，系统性识别 AI 代答、简历注水与经历造假，为面试官提供客观的真实性参考。

### 2.2 传播定位

**hiredetector（招聘测谎仪）**

用大众易懂的概念传递核心价值：给面试环节装上"测谎仪"，不靠主观感觉判断，用系统化方法核验真实水平，记忆点强、传播门槛低。

### 2.3 核心价值

- **精准辨真**：通过五层问题体系穿透 AI 套话，高效识别无实操经验的"简历选手"。
- **降本提效**：自动生成针对性面试提纲，替代面试官人工设计细节问题，缩短初筛时间。
- **标准统一**：输出可复用的核验框架，降低面试官个人经验差异带来的判断偏差。
- **维护公平**：过滤 AI 注水的虚假简历，让真正有实操经验的候选人脱颖而出。

## 三、核心功能模块

### 3.1 简历深度核验引擎

- 自动解析 PDF/DOCX 简历，提取项目经历、技术栈、核心参数、量化指标等结构化信息。
- **细节陷阱生成**：针对简历中的具体数值、技术选型、项目决策，自动植入错误前提生成验证问题，通过候选人的纠错反应判断真实参与度。
- 矛盾点自动检测：识别简历中前后表述矛盾、不符合技术常识的内容，标记高风险项。

### 3.2 对抗性面试生成器

- **五层问题体系**：覆盖「体感类 → 细节类 → 踩坑类 → 决策类 → 认知类」，逐层穿透 AI 标准答案。
- 岗位模板适配：针对 AI 开发、后端、前端、运营等不同岗位，匹配专属核验策略与题库。
- 动态追问链路：基于候选人回答自动生成深度追问，打破预设答案的防御，模拟真实面试官的深挖逻辑。
- 反 AI 设计原则：所有问题规避"背诵即可作答"的八股题，主打个人体验、专属项目细节与决策过程。

### 3.3 回答真实性评估模块

- 五维评分模型：从**细节颗粒度、个人情绪体感、纠错反应、逻辑一致性、技术合理性**五个维度输出评分。
- AI 特征识别：自动识别模板化套话、通用方法论、无具体案例等典型 AI 生成内容特征。
- 风险分级输出：给出低/中/高三级风险提示，仅作为人工复核依据，不直接生成淘汰结论。

### 3.4 HR 初筛工作台

- 简历批量导入与解析，一键生成定制化面试问题清单。
- 面试记录与报告生成：实时标注回答疑点，自动输出真实性评估报告。
- 企业自定义配置：支持内部题库、评分权重、岗位策略的个性化配置。

## 四、技术架构设计

整体采用「Agent 编排 + 模块化能力 + 可扩展接入」的云原生架构，支持单机部署与私有化落地。

### 4.1 分层架构

1. **接入层**
   - Web 管理端：HR/面试官可视化工作台
   - RESTful API：支持对接企业现有招聘系统、飞书/钉钉应用
   - SSE 流式输出：问题生成、评估过程实时返回

2. **应用编排层（核心）**
   - 基于 LangGraph 构建多 Agent 工作流，统一编排简历解析、问题生成、动态追问、真实性评估全链路。
   - 统一 Orchestrator 调度器：负责任务路由、状态管理、异常重试与模块降级。
   - 四大核心 Agent：简历解析 Agent、问题生成 Agent、动态追问 Agent、真实性评估 Agent。

3. **能力引擎层**
   - 大模型适配层：统一接入 DeepSeek、Qwen、OpenAI 等兼容接口，支持模型热切换与降级。
   - RAG 检索引擎：基于 Milvus + BGE-M3 构建岗位知识库、面试策略库、题库向量检索。
   - 结构化输出引擎：保障所有 Agent 输出格式统一，便于下游业务处理。
   - 文档解析引擎：支持多格式简历解析与信息提取。

4. **数据存储层**
   - PostgreSQL：存储业务数据、用户信息、面试记录、评估报告。
   - Milvus：向量数据库，存储题库、策略库的向量索引。
   - Redis：缓存热点问题、会话状态，提升响应速度。
   - MinIO：存储原始简历文件、导出报告等对象资源。

5. **基础设施层**
   - Docker / Docker Compose 一键部署
   - 统一日志与监控
   - 模块级熔断与降级机制，保障服务稳定性

- **正式标识**：GitHub 仓库、官方文档、代码命名、协议文件统一使用 **adverhire**。
- **传播心智**：所有对外宣传、社区内容、产品 slogan 统一以 **hiredetector（招聘测谎仪）** 为核心概念，降低理解门槛，强化记忆点。

### 5.2 开源规划

- 开源协议：MIT 协议，核心引擎与基础功能完全开源。
- 开源范围：简历核验引擎、基础面试策略库、核心 Agent 工作流、单机部署方案。
- 商业闭环：企业级功能（批量处理、API 集成、私有化部署、定制化策略）作为商业版增值服务。

1. **技术社区冷启动**：在 GitHub、掘金、V2EX、知乎发布「反 AI 面试作弊」主题内容，输出对抗性面试方法论，以 hiredetector 概念引爆话题。
2. **HR 圈层渗透**：面向 HR 社群、招聘从业者输出「AI 时代如何面试辨真假」实用干货，打造工具心智。
3. **内容生态建设**：持续输出不同岗位的面试陷阱题模板、辨真技巧，引导 UGC 传播。
4. **Slogan 体系**

## 七、风险与应对措施

### 7.1 舆情与伦理风险

- **风险**：可能引发"不尊重候选人""面试刁难"的舆论争议。
- **应对**：
  1. 明确工具定位：仅作为面试官辅助参考，不直接生成录用/淘汰结论。
  2. 问题设计原则：全部围绕候选人自述的简历内容展开验证，不提出格、无关的刁难问题。
  3. 对外传播强调：项目目的是还原真实能力、维护招聘公平，保护有真才实学的求职者。

### 7.2 技术效果风险

- **风险**：问题设计不合理、评估模型准确率不足，导致误判。
- **应对**：
  1. 内置策略库全部经过真实场景人工验证，持续迭代优化。
  2. 只输出风险等级与参考建议，最终判断由人工完成。
  3. 建立社区反馈机制，基于真实面试案例持续优化模型。

### 7.3 竞品跟进风险

- **风险**：概念出圈后快速出现同类产品。
- **应对**：
  1. 快速建立社区生态，沉淀用户贡献的策略库与行业模板，形成数据壁垒。
  2. 深耕垂直场景，从技术岗逐步扩展，做深做透而非大而全。

## 八、项目意义

AI 时代的招聘正在经历一场攻防不对等的博弈：生成式 AI 在帮求职者优化表达的同时，也模糊了真实能力的边界。

adverhire / hiredetector 的目标，不是打造刁难候选人的工具，而是建立一套公平的核验机制——让简历回归真实、让面试回归能力，帮助招聘方找到真正匹配的人才，也让踏实做事的求职者不被劣币驱逐。
